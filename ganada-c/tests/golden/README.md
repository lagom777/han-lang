# 골든 코퍼스 — 파이썬 없이 하는 회귀 검증

여기 있는 기대 출력은 **파이썬 구현(`가나다.py`)이 정답지일 때 한 번 뽑아 동결한 것**이다.
평소 검증은 이 코퍼스만 보면 되므로 파이썬이 없어도 된다.

```
make test        # 코퍼스 대조 — 파이썬 안 씀 (러너가 가나다로 쓰였고 C 바이너리가 실행)
make test-conform    # 교차 검증 — 파이썬으로 가나다.py 와 직접 대조 (tools/conform.py, 참고용)
make golden          # 코퍼스 재생성 (파이썬 필요)
make golden-check    # 코퍼스가 정답지와 여전히 같은지만 확인 (파이썬 필요, 쓰지 않음)
```

## 무엇이 들어 있나

| 구분 | 개수 | 출처 |
| --- | --- | --- |
| 케이스 | 305 | `tests/test_han.py` 를 AST로 파싱해 뽑은 `run(소스) == 기대` / 오류 부분문자열 단정 |
| 예제 | 80 | `examples/*.ㄱㄴㄷ` 의 stdout (87개 중 제외 7개 빼고) |
| 자가검증 | 2 | 러너가 정말 실패를 잡는지 증명하는 캐너리 |

빠진 케이스와 이유는 `제외.tsv` 에 전부 적혀 있다.

## 폴더 구조

```
목록.tsv          러너가 읽는 인덱스(탭 구분, # 은 주석). 이것만이 러너의 입력이다.
제외.tsv          코퍼스에서 뺀 케이스 + 이유 (사람 리뷰용)
케이스/           test_han.py 유래
  0001_test_hello.ㄱㄴㄷ      소스 (그대로 손으로도 실행 가능)
  0001_test_hello.기대        기대 stdout — 바이트까지 정확히 일치해야 한다
  0010_test_for_step.오류     기대 오류 문구 — stderr/stdout 에 이 부분문자열이 있어야 한다
  0010_test_for_step.오류원문 정답지(파이썬)가 실제로 뱉은 메시지 — 참고용, 러너는 읽지 않는다
  0305_..._입력_EOF없음.입력  표준입력 (필요한 케이스만)
  examples/lib.ㄱㄴㄷ         가져오기 대상 고정 자료 — 코퍼스를 자립시키려 복사해 둔 것
예제/
  hello.기대                  examples/hello.ㄱㄴㄷ 의 기대 stdout
  input.입력                  표준입력 (필요한 예제만)
자가검증/
  통과.ㄱㄴㄷ / 통과.기대     맞는 기대값 — 통과해야 한다
  실패.ㄱㄴㄷ / 실패.기대     일부러 틀린 기대값 — 반드시 실패해야 한다
```

예제는 소스를 복사하지 않고 원본 `examples/*.ㄱㄴㄷ` 를 가리킨다. 예제를 고치면 골든이
바로 불일치로 잡히므로(= 의도한 신호), 그때 `make golden` 으로 다시 동결한다.

## 목록.tsv 칸

| 칸 | 뜻 |
| --- | --- |
| 구분 | `케이스` \| `예제` \| `자가통과` \| `자가실패` \| `합계`(첫 줄, 총계 기록) |
| 이름 | 실패 보고에 쓰는 케이스 이름 |
| 검사 | `출력`(stdout 완전 일치) \| `오류포함`(부분문자열 포함) |
| 코드 | 기대 종료 코드 (정답지가 낸 값. 정상 0, 오류 1) |
| 소스 | 실행할 `.ㄱㄴㄷ` — 레포 뿌리 기준 상대경로 |
| 기대 | 기대값 파일 — 레포 뿌리 기준 상대경로 |
| 입력 | 표준입력 파일, 없으면 `-` (= `/dev/null`) |
| 작업 | 작업폴더. 경로면 그 폴더에서, `임시` 면 매번 비운 임시폴더에서 실행 |
| 유래 | 원본 테스트 함수명 또는 예제 파일명 |

첫 줄의 `합계` 행에는 생성기가 센 케이스·예제 건수가 들어 있다. 러너는 실제로 돌린 건수를
이 값과 대조하므로, 목록이 잘려 조용히 커버리지가 줄어드는 일은 실패로 잡힌다.

## 러너를 어떻게 믿나 — 자가검증 3중 장치

러너가 가나다로 쓰였다는 건 검사 대상 인터프리터가 러너를 돌린다는 뜻이다(순환 의존).
"항상 통과하는 러너" 가 되지 않도록 세 가지를 걸어 뒀다.

1. **캐너리** — `자가검증/실패` 는 일부러 틀린 기대값이다. 이게 통과로 나오면 러너가 비교를
   못 하고 있다는 증거이므로 코퍼스 대조를 시작하기도 전에 중단한다.
2. **합계 대조** — 위 참고.
3. **통과표** — 전부 통과했을 때만 작업폴더에 `통과표` 를 쓴다. `make test` 는
   러너 종료코드가 아니라 이 파일 존재로 성공을 판정하므로, 인터프리터의 오류 종료코드가
   깨져 `발생()` 이 0으로 끝나도(실제로 그 결함을 주입해 확인했다) 검사는 실패로 남는다.

작업폴더(`GANADA_GOLDEN_WORK`, 기본 `/tmp/ganada-golden-work`)에는 케이스별 임시칸과
stdout·stderr 캡처가 들어간다. **한 실행이 독차지해야 한다** — 두 검사가 같은 폴더를 쓰면
서로의 캡처를 덮어써서 없는 불일치가 수십 건 나온다. `make test` 는 그래서 실행마다 다른
폴더(`/tmp/ganada-golden-work-<PID>`)를 넘기고 통과 시 지운다(실패하면 진단용으로 남긴다).

## 결정성 — 어떻게 고정했나

케이스마다 환경을 고정한다. `tools/골든생성.py` 의 `FIXED_ENV`/`UNSET_ENV` 와
`tools/골든검사.ㄱㄴㄷ` 의 `고정환경`/`지울것` 이 **같은 값이어야 한다**.

- `HAN_TEST_VAR=값123` — `환경변수` 테스트가 요구
- `HOME=/ganada-golden-home` — `env.ㄱㄴㄷ` 가 HOME 을 찍는다(사람마다 다르면 동결 불가)
- `TZ=UTC`
- `OPENROUTER_API_KEY`·`OPENAI_API_KEY`·`ANTHROPIC_API_KEY` 는 unset — AI 예제를 stub 모드로 고정
- 표준입력은 `/dev/null` 또는 `.입력` 파일. 그 외 입력원은 없다
- 예제는 매번 새로 비운 임시폴더에서 돌린다(파일 쓰는 예제가 서로 간섭하지 않게)

생성기는 케이스마다 정답지를 **두 번** 돌려(예제는 서로 다른 임시폴더에서) 결과가 다르면
비결정적으로 보고 `제외.tsv` 로 뺀다. 실제로 이 검사가 `가나다셸.ㄱㄴㄷ`(프롬프트에
`현재위치()` 를 찍어 작업폴더 경로가 새는 예제)를 잡아냈다.

## 기대값이 바뀌어야 할 때

언어 동작을 일부러 바꿨다면 코퍼스를 다시 동결해야 한다 — 파이썬 정답지가 있는 환경에서
`make golden` 을 돌리고, **diff 를 사람이 읽어** 의도한 변화만 들어갔는지 확인한 뒤 커밋한다.
정답지 없이 기대값을 손으로 고치면 이 코퍼스의 의미(파이썬 구현과의 동등성 증명)가 사라진다.
