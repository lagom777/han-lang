# 가나다 — 말

숫자와 기호에서 출발한 언어. C의 뿌리에서 시작해, C가 버린 것을 기계가 지킨다.
한글은 그 숫자의 이름이다. 낳기가 그 숫자를 기계어로 바꾼다.

```
1  숫자     0 1 2   명령 번호 · 값 · 집 주소
2  기호     + - * / % = == != < > { } ( ) " # ,
            & | ^ ~ << >> ..
3  이름     만약 아니면 동안 멈춤 계속 출력 묶음 돌려주기
            열기 만들기 읽기 쓰기 닫기 집읽기 집쓰기 인수열기 인수만들기 실패
            그리고 또는 열만들기 열읽기 열쓰기 열길이 각각
```

값은 부호 있는 64비트 정수 하나다. 참은 `1`, 거짓은 `0`.
`4294967296` 은 2의 32제곱이다. 32비트에서 잘리지 않는다.
이름은 한글만. 칸은 묶음마다 32개.
집은 바이트 열이다. 주소가 숫자다.

열은 길이를 앞에 둔다. `열읽기`/`열쓰기`가 범위를 넘기면 기계가 멈춘다.
`각각 수 수들 { }` 는 그 길이를 고리로 쓴다. 인덱스를 직접 안 잰다.
`각각 이 1..4 { }` 는 닫힌 범위다. 넷이다. 끝난 뒤 `이`는 마지막 값이다.
`열만들기("ABC")` 는 널 없는 바이트 열이다. 길이가 3이다.
`그리고`/`또는`은 단락한다. `0 그리고 찍(1)`은 `찍`을 부르지 않는다.
`& | ^ ~ << >>`는 비교보다 먼저다. C의 `flags & MASK == 0` 함정은 없다.
나누기 영, 집 범위, 더하기·빼기·곱의 넘침도 트랩이다. C는 그걸 정의하지 않았다.

인자 하나인 묶음은 레지스터로 부른다. `rdi`로 들어가 `r9`에 머물고 `rax`로 돌아온다.
재귀 `피보(수-1)+피보(수-2)` 는 값 칸을 거치지 않는다. CPU의 `call`/`ret`다.
`+=` 고리는 칸을 레지스터에 올린다. gcc -O0보다 빠르다.
한글은 이름이다. 기계어에는 숫자가 남는다.

## 묶는 길

```
.ㄱㄴㄷ  →  첫묶기(ELF)  →  .ㄱㅂ 숫자  →  낳기  →  ELF  →  CPU
```

묶기 정본은 `컴파일러/첫묶기.ㄱㄴㄷ` 이다. 자기 소스를 다시 묶어 같은 `.ㄱㅂ` 가 나온다.
낳기는 그 숫자를 x86-64 기계어로 낳는다. 가상 해석은 없다. CPU가 바로 달린다.

시드는 어셈블리다. `as` 가 읽는 자리만 영어다. 그건 기계와 말하는 씨앗이다.
`시드/뼈.s` 는 모든 ELF 안의 손(출력·집·파일). `시드/낳기.s` 는 숫자를 기계어로 옮긴다.
